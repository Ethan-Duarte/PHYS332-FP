# N-Baddies — Deep Learning Guide, Volume I: From particle arrays to equilibrium galaxies

**Start here for the theory and source-code architecture.** This guide teaches the *current
implementation*, including its approximations and what it does not yet establish. The order
follows the mathematical skeleton first, then the code mapping, then a worked example. All
code paths below are in the V1.5 archive. Read the files alongside these explanations.

## 0. The entire system in five mathematical objects

A simulated galaxy is represented by particles with coordinates, velocities and masses:

\[
\mathbf x_i\in\mathbb R^3,\quad \mathbf v_i\in\mathbb R^3,\quad m_i>0,
\quad i=1,\ldots,N.
\]

They are stacked into arrays `x` `(N,3)`, `v` `(N,3)`, `m` `(N,)`.

The simulator also has:

- **The force operator** \(F:\{x_j,m_j\}\mapsto\{a_i\}\). In our code, choose
  `gravity/direct.py`, `gravity/fast_direct.py`, or `gravity/fast_barnes_hut.py`.
- **The time-step map** \(L_{\Delta t}:(x,v)\mapsto(x',v')\) implemented by
  kick–drift–kick `integrate.py`.
- **The initial-condition sampler** \(S:f(x,v)\mapsto\{x_i,v_i,m_i\}\),
  implemented by the native Plummer sampler, approximate native disk sampler or AGAMA DF sampler.
- **The measurement function** \(D:\{x(t),v(t),m\}\mapsto\{\text{diagnostics}\}\),
  provided by `diagnostics.py`, `spirals.py`, and `validation.py`.

This is an end-to-end numerical experiment:

```
physical parameters -> distribution function -> particles -> acceleration
                                            -> leapfrog -> snapshots -> diagnostics
```

The UI is a controller of these objects, not another gravitational physics model.

### Worked example: one massless test particle

A particle at \(x=(1,0,0)\) around a central mass \(M=1\), \(G=1\),
without softening, feels \(\mathbf a=(-1,0,0)\). For a circular orbit its
speed is \(v_c=\sqrt{GM/r}=1\), so \(v=(0,1,0)\). The data structures are
still exactly the same as for a million-particle disk. Only the force sum changes.

## 1. Force calculation: Newton's equation as an operator

Newton's equations are

\[
\frac{d\mathbf x_i}{dt}=\mathbf v_i,\qquad
\frac{d\mathbf v_i}{dt}=\mathbf a_i.
\]

Our pairwise force uses Plummer-style gravitational softening:

\[
\mathbf a_i=\sum_{j\ne i}
\frac{Gm_j(\mathbf x_j-\mathbf x_i)}
{(|\mathbf x_j-\mathbf x_i|^2+\epsilon^2)^{3/2}}.
\]

**Why \(\epsilon\)?** Each numerical particle can represent many physical stars or a parcel
of dark matter. We do not want unrealistically strong two-body impulses caused by this
coarse representation. The softening length moderates short-range forces.

**Why it matters to AGAMA:** AGAMA's smooth self-consistent potential is not *automatically*
the softened potential generated by our finite particle sample. Even a mathematically
stationary DF can heat, puff up, or drift when represented with too few particles and
the wrong softening.

**Software mapping:** `nbody/gravity/fast_direct.py` loops over every pair and sums
forces; `nbody/gravity/fast_barnes_hut.py` groups distant masses using an octree.
The arrays are shared; you can change force solver without regenerating initial conditions.

### Worked example: softening changes the central force

Set \(r=\epsilon\). The softened acceleration magnitude is

\[
a_\epsilon=\frac{GM\epsilon}{(2\epsilon^2)^{3/2}}
=\frac{GM}{2^{3/2}\epsilon^2}.
\]

The unsoftened force at the same separation is \(GM/\epsilon^2\). Thus softening
reduces the magnitude to about 35.4% of the Newtonian value. This is a significant
change near the force-resolution scale, not just a way of preventing division by zero.

## 2. Time integration: what leapfrog actually preserves

The velocity-Verlet / kick–drift–kick map is

\[
\begin{aligned}
\mathbf v_{n+1/2}&=\mathbf v_n+\frac{\Delta t}{2}\mathbf a(\mathbf x_n),\\
\mathbf x_{n+1}&=\mathbf x_n+\Delta t\mathbf v_{n+1/2},\\
\mathbf v_{n+1}&=\mathbf v_{n+1/2}+\frac{\Delta t}{2}\mathbf a(\mathbf x_{n+1}).
\end{aligned}
\]

The computation of \(\mathbf a(\mathbf x_{n+1})\) happens **after** the position
update. This is why the algorithm needs a fresh force evaluation each step.

For a fixed separable Hamiltonian and exact conservative forces, leapfrog is
symplectic and second-order accurate globally. It typically exhibits bounded,
oscillatory energy error rather than systematic drift over moderate time horizons.
**Approximate Barnes–Hut force evaluations are not guaranteed to preserve those ideal
properties.** That's why we measure energy rather than assume it.

### Worked example: integration refinement

Run the same initial particles with \(\Delta t\) and \(\Delta t/2\) to the same
physical time \(T\). If the time step is the dominant error, the trajectory
error in the second-order regime should shrink by approximately four when
halving \(\Delta t\) (because it scales as \(\Delta t^2\)).

We do not infer the order from *one* two-run difference. A third resolution is
needed to see the scaling clearly. V1.5 implements the practical two-run first
screen; the full refinement grid remains future work.

**Where:** `nbody/integrate.py` (dynamics), `nbody/validation.py` (two-run comparison).

## 3. Density is not equilibrium

Density is a function of **position**:

\[
\rho(\mathbf x)=\int f(\mathbf x,\mathbf v)\,d^3\mathbf v.
\]

The six-dimensional function \(f(\mathbf x,\mathbf v)\) is the **distribution
function** (DF). Many different DFs can have the same density.

For example, put many stars in an exponential disk. Giving them all zero velocity
produces the requested **initial** density, but the disk collapses. Giving them
circular velocities calculated using the **wrong** mass distribution can also
cause radial oscillations, bars and vertical thickening.

The governing equation for a collisionless stellar system is the collisionless
Boltzmann equation (CBE):

\[
\frac{\partial f}{\partial t}
+\mathbf v\cdot\nabla_{\mathbf x}f
-\nabla\Phi\cdot\nabla_{\mathbf v}f=0.
\]

An equilibrium model has \(\partial f/\partial t=0\) in its own potential.
The potential must also satisfy Poisson's equation:

\[
\nabla^2\Phi=4\pi G\rho,\qquad
\rho(\mathbf x)=\int f(\mathbf x,\mathbf v)\,d^3\mathbf v.
\]

**The key coupling:** the DF determines the density, the density determines the potential,
and the potential determines which DFs constitute equilibrium.

**Where:** `galaxies/sources/native.py` knows how to sample densities, while the new
`galaxies/sources/agama.py` uses an external library to build a compatible DF and potential.

### Worked example: why the V1.4 preview heated

Our native disk's particles had plausible *initial positions* and approximate
streaming velocities, but their random radial and vertical velocity dispersions
were not generated from a self-consistent DF. The disk then changed thickness
and velocity dispersion dramatically when evolved in isolation. Small energy
drift cannot rescue it: an accurate integrator can accurately evolve an
out-of-equilibrium physical state.

## 4. Three mass profiles in the Mice-inspired galaxy

We use three interacting live components, all expressed in the same `G=1` code units.

**Disk:**

\[
\rho_d(R,z)=\frac{M_d}{4\pi R_d^2z_d}
 e^{-R/R_d}\operatorname{sech}^2(z/z_d).
\]

The factor \(2\pi R\,dR\) in a cylindrical ring gives a radial PDF
\(p(R)\propto R\exp(-R/R_d)\), not just \(\exp(-R/R_d)\).

**Hernquist bulge:**

\[
\rho_b(r)=\frac{M_ba_b}{2\pi r(r+a_b)^3},\qquad
M_b(<r)=M_b\frac{r^2}{(r+a_b)^2}.
\]

**Cored Dehnen halo, \(\gamma=0\):**

\[
\rho_h(r)=\frac{3M_ha_h}{4\pi(r+a_h)^4},\qquad
M_h(<r)=M_h\left(\frac{r}{r+a_h}\right)^3.
\]

Our reference masses are \((M_d,M_b,M_h)=(0.1875,0.0625,1)\).
The total is 1.25, so the disk is 15% of the mass, bulge 5%, halo 80%.

**AGAMA's common `Spheroid` family** has inner logarithmic slope `gamma`,
outer slope `beta`, and transition sharpness `alpha`. Using `alpha=1, beta=4`
with `gamma=1` gives Hernquist; using `gamma=0` gives the cored Dehnen halo.

**Subtlety:** AGAMA's DF-based self-consistent model can produce mass profiles
slightly different from the initial analytic density request. In addition,
AGAMA's halo has a finite total mass but is not **hard truncated** at the
native preview's sampling cutoff. Do not compare their samples as if they
were identical density laws.

## 5. The idea behind AGAMA: actions and distribution functions

In integrable or approximately integrable galactic potentials, stellar orbits can be
labeled by approximately conserved **actions**:

\[
\mathbf J=(J_r,J_z,J_\phi), \qquad J_\phi=L_z.
\]

A rough mapping:

- \(J_r\): amplitude of radial oscillation about a guiding-center radius.
- \(J_z\): amplitude of vertical oscillation through the disk.
- \(J_\phi=L_z\): angular momentum about the disk axis and related rotational support.

A stationary DF may be expressed as a function of integrals of motion,
including the actions: \(f(\mathbf J)\). This is related to **Jeans' theorem**.

AGAMA offers a `QuasiIsothermal` disk DF that favors nearly circular, rotationally
supported orbits with specified radial and vertical dispersions.
Our bulge and halo use `QuasiSpherical` DFs constructed from the requested
density and the initial, spherically averaged gravitational potential.

Saying "quasi" is important: real three-component disks are not perfectly spherical,
and their actions, kinematics, and realized density are approximations. The
self-consistent iteration updates the potential and densities until the
numerical model stabilizes under the selected assumptions.

**Where:** all these AGAMA interfaces are called in `galaxies/sources/agama.py`.
AGAMA itself is a compiled dependency, not a Python function we reimplemented.

## 6. The self-consistent AGAMA iteration in linear-algebra form

Think of the potential and DF as coupled nonlinear operators:

\[
\rho^{(k)}=\mathcal R[f,\Phi^{(k)}],\qquad
\Phi^{(k+1)}=\mathcal P[\rho^{(k)}].
\]

The operator \(\mathcal R\) integrates DF orbits over velocities and actions to
form a density. The Poisson solver \(\mathcal P\) computes a new potential from
that density. The iteration seeks a fixed point:

\[
\Phi^*\simeq\mathcal P[\mathcal R[f,\Phi^*]].
\]

The sequence in `agama.py` is:

1. Construct AGAMA `Density` objects for all three components.
2. Construct a `SelfConsistentModel` with radial/cylindrical potential grids.
3. Add density-based components and run an initial `model.iterate()`.
4. Calculate a characteristic disk velocity dispersion and build three DFs.
5. Replace static density components with DF-defined components.
6. Call `model.iterate()` four more times.
7. Sample phase-space particles from the DFs in the final potential.

The numerical resolution and radial extent of the **smooth potential grids** are
separate from the number of **sampled N-body particles**. Increasing the particle
count does not automatically change the accuracy of the smooth potential grid.

**V1.5 improvement:** the old spherical grid ended at a radius of only about 1 code
unit while our halo extends considerably farther. The new grid extends past the
nominal preview cutoff and records the actual outer radius in the model report.

### Worked example: two different discretizations

Suppose AGAMA constructs a smooth potential using 50 spherical radial grid
points. You could then sample either 1,000 or 100,000 N-body particles from
the **same** DF. The continuum equilibrium remains the same, but particle
noise and close encounters behave differently. This is exactly why isolated
finite-N validation follows, rather than precedes, DF construction.

## 7. Toomre Q: why the disk dispersion matters

A local axisymmetric stellar-disk stability indicator is

\[
Q(R)=\frac{\sigma_R(R)\kappa(R)}{3.36G\Sigma(R)},
\]

where \(\Sigma\) is stellar surface density, \(\sigma_R\) the radial random
velocity dispersion, and \(\kappa\) the epicyclic frequency.

For near-circular orbits the angular frequency obeys

\[
\Omega^2(R)=\frac{1}{R}\frac{\partial\Phi}{\partial R},
\qquad
\kappa^2(R)=R\frac{d\Omega^2}{dR}+4\Omega^2(R).
\]

In the adapter, we evaluate the radial force at \(R_d\) and nearby points,
estimate \(\kappa\) numerically, and invert the Q formula:

\[
\sigma_R(R_d)=\frac{3.36GQ(R_d)\Sigma(R_d)}{\kappa(R_d)}.
\]

Then the AGAMA `QuasiIsothermal` DF is configured with an exponentially
declining radial dispersion scale length.

**Worked example:** At fixed \(\Sigma\) and \(\kappa\), doubling \(\sigma_R\)
doubles \(Q\). The warmer disk is generally more stable against local
axisymmetric disturbances — but it is **not** automatically immune to
non-axisymmetric bars and spirals.

**Critical caveat:** the GUI slider specifies a **target** Q near one disk scale.
The *realized* DF and the sampled simulation need not have exactly this Q.
The Fourier diagnostics' `Q_star` is also an approximate estimate from a noisy
finite-N softened potential, not an independent proof of equilibrium.

## 8. Sampling: a probability law becomes particles

An equilibrium DF is continuous, but a computer simulation evolves finitely
many particles. `GalaxyModel.sample(n)` returns an array of 6D coordinates
`(x,y,z,vx,vy,vz)` and associated particle masses.

We retain the component labels: `0=disk`, `1=bulge`, `2=halo`.
For a two-galaxy encounter, we also retain the progenitor labels `0` and `1`.

**Why preserve mass weights?** Not all sampling schemes require equal particle
masses. When computing centers, energy, dispersion, or Fourier amplitudes,
use mass-weighted expressions rather than unweighted averages.

For example the center of mass is:

\[
\mathbf x_\mathrm{CM} = \frac{\sum_i m_i\mathbf x_i}{\sum_i m_i}.
\]

`particles.py` subtracts the total center-of-mass position and bulk velocity
from each generated galaxy. It does not "equilibrate" the galaxy; it simply
puts the galaxy into a convenient rest frame.

**New V1.5 behavior:** When initializing two AGAMA-generated progenitors we
build the smooth model *once* and sample it *twice* using different random
seeds. If you use a saved single snapshot as both progenitors, you still
reproduce the same finite-N particle noise in both (with different rotations),
and the run's metadata explicitly records that correlation.

## 9. How to test equilibrium without confusing it with accurate integration

The first test evolves one galaxy **alone**, with nothing to disturb it.
This is the *isolated galaxy* experiment.

We measure, among other things:

- Disk radial half-mass radius \(R_{50}\).
- Vertical root-mean-square disk thickness \(z_\mathrm{rms}\).
- Radial velocity dispersion \(\sigma_R\).
- Total energy of our **softened** gravitational model.
- Azimuthal spiral amplitudes \(|A_m(R,t)|\).

For a structural quantity \(X\), report

\[
\delta_X(t)=\frac{X(t)-X(0)}{X(0)}.
\]

**V1.5 `validation.py`:** run a saved realization twice, at \(\Delta t\)
and at \(\Delta t/2\), over exactly the same interval. Save both trajectories
and separate isolation plots and a combined JSON report.

This compares **numerical consistency**. If the galaxy collapses in both runs,
then the integrator may be converged while the physical initial conditions
are unusable for our intended Mice reconstruction.

### Worked example: why endpoint energy isn't enough

A numerical integrator might produce energy at `t=0` equal to -10.000 and at
`t=1` equal to -10.001 (relative change 0.01%). Meanwhile, the disk thickness
can double if the initial velocities were inconsistent or finite-N scattering
is strong. Energy conservation is a necessary diagnostic for an isolated
Hamiltonian system, but it does not constrain morphology to be static.

**Where:** `nbody/validation.py`, `nbody/diagnostics.py`, GUI **Test a saved
equilibrium galaxy** tab.

## 10. Spiral arms are measurements, not a proof of correctness

For disk particles in a radial annulus, define

\[
A_m(R,t)=\frac{\left|\sum_{j\in\text{annulus}}m_j e^{im\phi_j}\right|}
{\sum_{j\in\text{annulus}}m_j}.
\]

\(m=1\) is lopsided structure, \(m=2\) can be a two-armed spiral *or a bar*, and
higher \(m\) correspond to increasingly fine angular modes. A single global
\(A_2\) can cancel across radii when spiral phases wind up, so `spirals.py`
measures annular amplitudes and phases.

For independently sampled particles of similar mass, the RMS random mode
amplitude scales roughly like \(1/\sqrt{N_\mathrm{eff}}\), with
\(N_\mathrm{eff}=(\sum m_i)^2/\sum m_i^2\).

The observed rise and decline of the preview disk's `A2` could be affected by
spiral amplification, bar formation, transient initial relaxation, finite-N
fluctuations and disk heating. The point of V1.4.1 and V1.5 is to make
those possibilities testable.

## 11. Binary orbits and the eventual observed Mice

An isolated galaxy starts in its own center-of-mass frame. The encounter code
rotates each galaxy's disk and adds bulk orbital positions and velocities.

For an ideal two-body parabolic encounter with total mass \(M_1+M_2\), the
specific energy is zero and at separation \(r\):

\[
v^2=\frac{2G(M_1+M_2)}{r}.
\]

Specifying nominal point-mass pericenter \(r_p\) determines the angular
momentum scale, but **live deformable halos do not necessarily reach that
exact pericenter**. Actual closest passage must be measured from the evolved
particle distribution.

The original Barnes Mice model motivates our masses, morphology and
orientations. AGAMA equilibrium is not a guarantee that our collision reproduces
that published model exactly: the N-body discretization, halo assumptions,
softening, orbital epoch and missing gas dynamics still matter.

Our observational strategy must compare **projected** tail geometry, galaxy
core separation and eventually appropriate line-of-sight velocity constraints,
including uncertainties. A good animation alone cannot establish validity.

## 12. Direct versus Barnes–Hut: comparing *equations* and *algorithms*

Direct summation computes all pair accelerations and costs \(O(N^2)\).
Our compiled direct code has low overhead and is an accurate internal reference.
Barnes–Hut reduces distant groups to approximate multipoles and is often
\(O(N\log N)\) in favorable conditions, but the constant costs of tree
construction/traversal can make it slower at modest \(N\).

A fair comparison uses **identical initial particles**, the same softening
law, the same timestep and the same physical duration. The BH opening
angle \(\theta\) varies, but the force law does not.

For per-particle force error:

\[
\delta a_i=\frac{|\mathbf a_{i,\mathrm{BH}}-\mathbf a_{i,\mathrm{direct}}|}
{|\mathbf a_{i,\mathrm{direct}}|}.
\]

A near-zero reference acceleration can inflate this ratio, so also examine
absolute acceleration errors and the distribution of errors across particles.

**The further scientific question:** Even if individual particle trajectories
diverge after a long encounter, do the large-scale tidal properties agree at
a level significantly better than the physical differences being studied?

**Where:** `nbody/solver_study.py`, `nbody/benchmarks.py`, corresponding GUI tabs.

## 14. Guided exercises with worked answers

**Exercise A: resolution and relative error.** If force error from BH is 0.8%
and a measured physical difference between two configurations is 0.4%, can
you infer which configuration has a longer tail? **No**; the force error alone
is not necessarily equal to tail error, but the physical effect is smaller
than the force discrepancy. You must directly converge the tail observable.

**Exercise B: global modes.** If half the annuli have a positive complex
`m=2` amplitude and the other half have the same magnitude but negative
complex amplitude, what is the global amplitude? **Zero**, despite strong
local two-armed structure. Use annular amplitudes and phases.

**Exercise C: changing G.** If AGAMA's `setUnits` changes the numerical value
of `G` from 1 to another constant but we still calculate orbital velocity
using \(v=\sqrt{M/r}\), is the code physically consistent? **No**. The
units and the numerical gravitational constant must agree in *every* stage.

**Exercise D: convergence versus validation.** Suppose \(\Delta t\) and
\(\Delta t/2\) runs both predict 50% disk thickening. Does their agreement
validate the equilibrium galaxy? **No**. It may establish that the thickening
is not a timestep artifact. It remains necessary to determine whether it
is a physical instability, sampling/softening artifact or disequilibrium.

**Exercise E: source compatibility.** The AGAMA source archive is present but
`import agama` fails. Is our `agama.py` adapter necessarily wrong? **No**.
The native C++ extension may not have been compiled or installed in the same
Python environment. Test import first, then test construction and sampling,
then test isolated evolution.
